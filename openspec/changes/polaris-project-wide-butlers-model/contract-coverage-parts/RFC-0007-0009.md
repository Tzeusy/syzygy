## Bottom line

[Inferred] The candidate correctly makes full-project order, progressive category paths, declared-shape denominators, current/proposed separation, project-wide channel parity, the core cold-open prompts, and much of the record/judgment fail-closed protocol observable.

[Observed] It does not currently provide PWB oracles for the highest-risk RFC7 consequence gaps:

- universal claim classification and anchor covering/minimality/bounding;
- Polaris non-authority and non-citability;
- typed target-state anchors and drift;
- verbatim operative text;
- the complete capability deep-dive authority-band contract;
- status label+tier+reason+freshness and no-composite behavior;
- drawer/scheduler authority sourcing;
- proposal scenario context, exclusivity and no-anchor/no-green behavior;
- full machine attributes, especially `non-citable` and narrative-claim type;
- nonvisual disclosure-path traversal;
- reusable material-change review scheduling;
- full walkthrough execution/judgment fields and `verdict-unlawful`.

[Inferred] RFC8 and RFC9 should remain precise per-clause “believed not applicable” rows for this PWB change. Mapping them merely because the signed parent has Trajectory/Orrery behavior would conflate inherited parent scope with the candidate’s actual capability and would recreate the family-boilerplate error the audit was meant to prevent.
