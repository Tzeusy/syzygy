- [Observed] RFC2-24 is not covered anywhere. “Fixed reason” and “expected reasons” permit a private vocabulary; no oracle checks the closed twelve, exactly one primary, secondary values, resolution routes, or aggregate reason disclosure.
- [Observed] PWB-REQ-001’s RFC2-3 citation is false coverage. The requirement never exposes or tests the as-of instant and never proves evaluation identity is exactly `(snapshot, as-of)`.
- [Observed] Both RFC2-6 citations are false coverage. The candidate tests a shared live model, not an immutable observation record.
- [Observed] Both RFC2-7 citations are false coverage. The capability excludes inference; neither oracle observes an inference overlay consequence.
- [Observed] PWB-REQ-004’s RFC1-24 citation is false coverage. Conflict/precedence comparison does not prove positive status flows only through Claims and `supports`.
- [Observed] PWB-REQ-003’s RFC3-30 citation is false coverage. Its oracle does not establish per-pair consent or that only the observing project’s provenance-verified policy governs foreign content.
- [Unknown] The candidate’s `contradicted` coverage state is not tied to RFC1-18(b)/RFC2-15 Contradiction identity. Because PWB-REQ-004 permits explicit precedence, the omission is load-bearing: ordinary conflicting declarations and co-unsatisfiable authoritative claims must be distinguished.
- [Unknown] The custom `(source class, path, declared key)` identity may represent a surface-local record or a new graph entity. If it represents Capability or another declared RFC1 class, path-bearing rename semantics conflict with RFC1-10; if it is a new kernel entity, RFC1-5/7 coverage is absent.
- [Observed] No owner-reviewed N/A judgments exist. Therefore every “believed not applicable” disposition remains non-binding, and every uncovered applicable consequence remains Unknown under RFC1-33/RFC2-26/RFC3-33.
