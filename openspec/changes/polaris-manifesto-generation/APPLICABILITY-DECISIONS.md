# Proposed generator applicability judgments

Owner decision subjects for the RFC7-38 coverage gate. These proposals bind
nothing until their exact scope is reviewed and an effective owner act records
the judgment in the governing decisions home. The coverage matrix is evidence,
not that act. No workspace/portfolio behavior is removed from its owning contract.

## The unit of generation is one project

The generator produces one project's manifesto per run and can repeat the same
process for other admitted projects. It does not introduce an owner Workspace
entity, membership/grouping/order/saved-view editing, or a portfolio-level
narrative. A project picker selects admitted projects; it does not persist a
workspace composition or make portfolio claims. A request for a workspace or
portfolio composition is explicitly unsupported by this operation rather than
silently treated as one project.

This does not exclude project relationships or declared child-project composition.
Those project-local obligations remain in requirements 004, 026 and 027, with
counterpart confirmation, source permissions and child epistemics intact.

| Proposed judgment | Exact consequences | Rationale and preserved boundary |
|---|---|---|
| GNA-1 | RFC7-35 workspace artifact, arrangement/truth separation and workspace-entry behavior; matrix rows RFC7-35.c01-c03; the workspace manifest residence, closed fields, project-identity references, arrangement/local-state and truth-separation consequences of RFC3-10 through RFC3-13 | No workspace artifact or editor is introduced. Project selection is not workspace arrangement. Existing workspace obligations remain for their owning capability. |
| GNA-2 | RFC7-36 portfolio narrative, its carried authoring/provenance/drift/parity/accessibility rules, and its claim/status boundary; rows RFC7-36.c01-c03 | No portfolio narrative is produced or rendered. The same authoring and truth disciplines still apply to every generated project narrative through its mapped requirements; this is not an exemption from them. |
| GNA-3 | RFC7-29's owner-workspace portfolio narrative consequence; row RFC7-29.c08 | Its project-profile, authoring and reading consequences remain mapped. Only the portfolio-narrative consequence is outside the per-project generator operation. |

These are not claims that a clause is irrelevant merely because implementation
is inconvenient. A new workspace/portfolio output would retire this scope basis
and require the appropriate specification/authority before being exposed. Two
real project manifestos using the unchanged generator remain required and are
not discharged by these judgments.

## Work activity is not covered by these N/A proposals

The staged worker-projection boundary in EXECUTION-PHASES.md is separate. Required
work consumers still follow requirement 028. Unsupported mappings refuse the
affected live admission; no new activity predicate, blanket work-state exemption
or owner N/A is asserted here. The independent no-signal amendment draft is
retained outside this specification subject and remains unperformed.

## Conditional operations not introduced

The operation never executes observed-project code or provider-supplied programs;
no observed-code launcher/execution profile is activated. Trusted registered
adapters and the generator's own implementation are distinct from observed code.
Any later launcher would require its own execution-profile and contract coverage.

The drafting-run view does not create or edit Personal Intake or import arbitrary
inherited backlog as new warranted work. An existing binding is reusable only
through the explicit immutable join, current eligibility and remaining-authority
checks; missing or conflicting provenance cannot be repaired by retroactive
warrants. The selected-run scope is shown, not described as all project work.

Computed visual production is disabled in the initial version as specified in
ASSET-CONTRACT.md. Recognized requests fail honestly rather than activating a
renderer by inference. Its conditional rendering obligations remain attached to
any future enablement; this is not a waiver for something actually rendered.
These conditional applicability rationales still need the package's independent
coverage review and do not override any required owner-judgment gate.
