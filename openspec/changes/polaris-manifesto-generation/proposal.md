# Polaris manifesto generation

Candidate — binds nothing. Specification adoption, implementation authorization,
project admission, provider consent, authorship and release remain separate acts.

## Why

Polaris should make a project's purpose and ideas understandable through a
coherent, beautiful, browsable account. The current Butlers page uses fixed copy
and manually selected passages; it cannot reliably generate or regenerate that
experience for another project.

## What Changes

- A project-neutral, human-triggered generation workflow using authorized source
  snapshots and explicitly permitted providers.
- Structured editorial drafts, with source-backed motives, concepts, claims,
  Unknowns, navigation and optional relationship assets.
- Bounded editorial construction, independent fidelity/design review and revision.
- Observable cancellation, recovery, source-drift regeneration and preservation
  of human-curated presentation.
- Contextual review/adoption in Polaris, using the existing human-act predicate;
  drafting lifecycle remains owned by Trajectory.
- Reusable asset rendering and separately authorized export without source-code
  changes for each project.

## Capabilities

### New Capabilities

- `polaris-generation`: Generate, review, recover and adopt project-specific
  manifesto presentation from admitted snapshots through one reusable workflow.

### Modified Capabilities

Existing PWB observation, exact-text and truth-projection requirements remain
intact. Host authentication and credential handling require explicit integration
for the new data-bearing and mutating generation operations: session/anti-forgery
admission, project scopes, verifier-only server storage and protected audit cannot
be assumed from current read-only route helpers. The overlap/impact review must
identify any corresponding amendment to existing capability behavior before
sign-off; the earlier blanket claim of no modified capability is not established.
This is not a replacement source-observation policy.

## Impact

The app needs a project-neutral presentation input and generation controls.
The source/permission adapters, narrative renderer, drafting lifecycle and
provider interface need explicit integration. No library, provider, storage
engine or deployment is selected by this proposal.

In scope: the complete local owner experience, reusable generation and
regeneration, semantic/design validation, explicit draft/authorship states,
recovery, and permitted asset retention/export.

Out of scope: autonomous intent adoption, implementation-code generation or
writes, automatic release/deployment, unauthenticated remote service, multi-user
collaboration, implicit model-provider egress, or a second independent work queue.
These exclusions do not narrow cross-project generator reusability: independently
admitted projects must use the same implementation.

This proposal does not authorize reading another real project or sending Butlers
content to a provider. The existing PWB continuation explicitly excludes those
effects. Tests with synthetic bundles may establish mechanics but cannot discharge
real-project quality evidence.

## Exact implementation and applicability scope

EXECUTION-PHASES.md stages mechanics, the complete owner/effect flow, and real
quality/portability proof without shrinking completion. EFFECT-HOST-DESIGN.md
selects separate generator origin/process/credential stores and a protected local
recorder; legacy PWB/CAP1 routes retain their existing behavior. The host-overlap
inventory in docs/design/POLARIS-GENERATOR-HOST-OVERLAP.md records the exact
additive seams; a departure changing an adopted outcome still needs its signed
amendment rather than an implicit compatibility claim.

APPLICABILITY-DECISIONS.md proposes the narrowly scoped workspace/portfolio
judgments for owner review. No such judgment is effective yet. The generator
still handles project relationships and declared child composition as specified.
The independent RFC8 no-signal predicate amendment is not part of this specification
adoption subject; supported-profile admission and explicit later obligations
remain controlling.
