# Process lessons and incidents (non-default context)

> **Never authority, never default context.** This file is tracked so a clone
> can read the history behind the repository's operating rules. It binds
> nothing. Load it deliberately — for maintenance or review work, or when
> about to repeat something listed here — never as background reading.

**Provenance and home.** Migrated 2026-08-05 from the former `AGENTS.md`
"Notes to self" appendix, and relocated the same day from
`contracts/candidates/round-2026-08/` to this durable home: process lessons
outlive the round that discovers them, and a round record is the wrong place
for a rule that should still apply in a year. `AGENTS.md` keeps only the four
compressed **verification rules**; this file is their single incident record
and carries every phase-specific and machine-specific detail.

## Shell and tooling hazards (this machine)

- **Interactive aliases hang agents.** `cp`, `mv`, and `rm` are aliased to
  their `-i` forms; an agent's non-TTY shell waits forever on the prompt.
  Always pass `-f`.
- **Bash `cwd` persists across tool calls, but a subshell's does not.** A
  bare relative `>> FILE.md` after a `cd` into a git-excluded tree writes a
  file `git status` cannot see. Absolute paths under `_bootstrap/**`.
- **Never edit stored raw reviewer output.** When a checker flags a line
  inside a verbatim report, allowlist the file in the checker; changing the
  report destroys the evidence the allowlist exists to protect.

## Incident-backed rules

- **ugrep silent pattern failure (two incidents).** `grep` on the founder
  machine is ugrep 7.5.0. Rev8: `*(History:` literals needed `grep -F`. In
  the 2026-08-04 knowledge-refactor pass, the `[^]]` bracket class matched
  nothing, so a sweep "verified" zero markdown links in a tree containing
  13, and the false universal propagated into two artifacts before being
  caught. Rule: `grep -F` for literals, simple classes, or Python `re`;
  any zero-result sweep supporting a universal claim is unconfirmed until
  reproduced by a second method.
- **Overstated completeness claims (two incidents at rev8).** A "zero
  unprefixed History entries" claim was written without running the exact
  sweep, twice; a confirming reviewer caught it both times. Rule: never
  write a zero/100% claim without running the described sweep in the same
  session; enumerate remainders.
- **Self-count invalidation (rev10 residual R1).** A fix batch that touches
  a file invalidates that file's own self-referential counts: adding a
  section to RFC-0007's README staled its own "this index is N words" line;
  only the confirming reviewer caught it. Re-verify self-counts of every
  touched file after any batch. (R1 itself was corrected in this round's
  package revision.)
- **Verdict smoothing (rev10 residual R2).** A synthesis wrote "PASS with
  findings" for a review whose verdict line said EXCEPTIONS. Rule: copy the
  verdict word; the raw report's verdict line is the only source.
- **Garbled digests (two incidents).** Hand-transcribed sha256 digests were
  corrupted twice in craft records. Rule: digests are generated by script
  into the record, never typed.
- **Anchor breakage in batch prose edits.** Line-wrap breaks long literal
  anchors; the rev10 RFC-0011 batch aborted cleanly only because it was
  structured assert-all-then-write. Rule: short unique anchors or
  normalized whitespace, and nothing is written unless every anchor
  matched.
- **Stray-file hazard under excluded trees.** Bash cwd persists across
  tool calls; a bare `>> FILE.md` under the git-excluded `_bootstrap/`
  created files invisible to `git status`. Rule: absolute paths for
  appends there; verify with `find`.
- **Reviewer transport failures.** Fresh-context reviewer subagents
  reliably go idle without transmitting their report; request the full text
  explicitly (sometimes twice), or spawn reviewers as background agents
  whose final message arrives via task notification. Store raw output
  verbatim before synthesizing.
- **Parallel lead sessions.** The owner sometimes runs two sessions as
  co-leads on one pass (2026-08-04: a duplicate §20 review battery, stored
  as `20-Nb-*-respawn-RAW.md` with delta index `20-RESPAWN-DELTA-INDEX.md`
  in the bootstrap tree). Before respawning "dead" reviewers or editing
  tracked files after a resume, check the bootstrap checkpoint tail and
  review-file mtimes for a live parallel lead.

## Added at the round close (2026-08-05)

- **A derived value quoted for convenience is a promise, and an unchecked
  promise goes stale silently.** This round's headline defect was four act
  digests that were correct in their manifests and stale in the document that
  offered them; six of eight independent reviewers found it and no amount of
  authoring care did, because the author had written every record that made it
  discoverable. The durable fix is not vigilance — it is `check_governance.py`
  CG-7d, which compares *every* copy of an act digest anywhere in the corpus
  against its subject. On its first run it found a fifth stale copy (craft
  `INSTALL-RECORD.md:51`) that no reviewer had reported.
- **A check that covers one member of a population, truthfully, still reads as
  coverage.** CG-7 had reported "1 argument examined, 0 findings" for months
  over a population of four acts. The line was honest and the impression it
  gave was false. Report the denominator, and check whether it is the whole
  population.
- **Historical quotations need a marker the tooling can see.** CG-7d exempts a
  digest only when its own preceding text on the same line marks it
  retired/stale/superseded/historical — a marker *later* in the line does not
  exempt it, because the acceptance record's rows legitimately say "the rev9
  argument is stale" right after offering the current one.
- **Test the tools against the environment they claim to support.** Running
  the clone-equality test at final bytes found that `check_governance.py`
  aborted after one WARN outside a git checkout, running none of its 21 other
  checks. A real clone is a git checkout and never hit it; an archive download
  would have received a silent one-line non-answer. It now degrades to a
  filesystem walk and reports the unknowable check as Unknown.
- **Run the acceptance test, do not reason about it.** Charter Test C passed —
  and produced the round's two most useful structural findings (the routing
  indexes route no doctrine or craft source; doctrine selection granularity
  cannot honor RFC11-1 as written). Neither was visible from reading.
- **Marker windows must be whitespace-normalized.** A marker and the pointer
  it justifies routinely land on opposite sides of a line wrap in prose;
  a line-based matcher then manufactures findings. Same root cause as the
  recorded anchor-breaks-on-wrap lesson for batch replacement.

## Round 2026-08b — checks, and what they cost to get right

- **A citation is not a reliance.** A dependency sweep that asked "does the
  target cite the source's clauses" added four wrong edges, because two
  citation shapes are not reliances: the boilerplate `RFC3-16` status banner
  every module carries (RFC-0001 carries it too, and declares
  `depends_on: []`), and the `(Shape-parallel with RFC6-28, …)` parenthetical,
  which says two clauses have the same *shape* — the opposite of consuming
  one. The decisive test a reviewer used: RFC7-38 appears in the same
  parenthetical on the same line, yet RFC-0007 does not declare the edge.
  Identical evidence, opposite treatment, so the evidence was never doing the
  work.

- **Two checks reported OK over zero examined items.** CG-14's first version
  regex-matched an install-route arrow form the record does not use; CG-18's
  first version anchored on a `(recompute` suffix and silently examined 4 of
  8 fixtures while printing a count. Both printed a truthful denominator that
  nobody read. `--selftest` exists because of this: one synthetic failing
  fixture per check, run in the same command.

- **A derived view that goes stale spends the reader's trust in everything
  near it.** A fresh engineer found two stale rows in the context-load map by
  hand, and correctly stopped believing the file. Eleven of eleven rows were
  stale. The map's own sentence said "all figures below are its output,
  re-runnable from this packet."

- **A published finding can be false, and false findings propagate.** "Adopted
  doctrine cites a README glossary that does not exist" reached five tracked
  artifacts. The glossary exists. The real defect — doctrine does not say
  *which* README, and the root one has none — is narrower and had been stated
  correctly by the original reviewer. The summary lost the qualifier, and the
  summary is what got copied.

- **Check the allowlist as carefully as the check.** A link-checker allowlist
  written for stale *history* references (`^(\.\./)*(topology|history|…)/`)
  silently absorbed a live *instruction* — an act's install source naming a
  directory that has never existed. The check reported "714 references
  examined, 0 findings" and was not wrong; it was blind.

- **Prefer disambiguating the artifact to teaching the checker to guess.**
  When CG-14 could not tell a bare `topology/` destination from a bare
  `topology/` source, the fix was to write the destination as its full path,
  not to add a fourth heuristic.

- **Run the checks in a clone, not only in the working tree.** At one commit
  this round `check_governance.py` reported 0 FAIL here and 1 FAIL inside a
  clone of the same commit. CG-14 asked the filesystem whether `_bootstrap/`
  existed; the founder machine has it, so a ceremony step depending on a
  git-excluded directory read as executable. Every check that resolves a path
  should answer from the tracked corpus or from `.gitignore` — never from
  local disk — or it verifies the machine rather than the repository.

- **A clone report is valid only for the commit it was run at.** The previous
  `PUBLIC-CLONE-VERIFICATION-REPORT.md` said "clone of commit 864718c" and
  carried an act-1 digest that had been edited into it after the manifest
  moved: a report describing one commit while quoting another. Re-run it;
  never patch its figures.

- **A whole-line exemption test is blind to wrapped prose.** CG-14's
  correction-marker regex matched per line, so a retraction paragraph whose
  "previously" and whose `_bootstrap/` landed on different wrapped lines read
  as a live instruction. CG-15 had already paid for this exact shape. The
  window has to be at least the neighbouring lines.

- **The pass that corrects defects introduces them.** The confirming review
  over the final bytes found three, all in this round's own corrective work: a
  clause written to close an escape that left one open, twenty-one stale
  derived values in the commit whose message said it had corrected every stale
  derived value, and a report misdescribing four of the seams it claimed to
  close. Commission the confirming review over the *exact bytes*, after the
  corrections, or it confirms something nobody is being asked to accept.
