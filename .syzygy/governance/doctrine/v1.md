# Scope — V0, V1, and deferrals

## V0 — the trustworthy observatory, with proof the loop is real

V0 observes, per governed project, **whatever Project Genome artifacts and
evidence exist** — doctrine and declared-topology documents
(`.syzygy/governance/`), spec structure (`openspec/`), work-scheduling state,
and code structure including on-disk test/CI artifacts. Absent artifacts render Unknown (VIS-2); the truth claim is
bounded by honesty, not by a source whitelist.

**The V0/V1 gap boundary:** V0 surfaces *absence* — a declared capability with
no mapped evidence, code mapping to no declared capability — rendered as
Unknown. V1 computes *gaps*: intent-vs-observed deltas as navigable,
work-generating objects. At V0 the Trajectory surface contains work-dependency
graphs and absence surfacing, not gap computation.

V0 ships (incrementally — see below):

- **Portfolio truth**: every governed project's vision, work state, and
  structural health, honest about what is Unknown.
- **Spatial code visualization**: the owner has mandated **3D** as V0's
  realization of the constitutional spatial requirement (architecture.md) — one
  projection over the stable project graph, with exact 2D/tabular views
  retained for precision, accessibility, and debugging, and keyboard/non-3D
  navigation always available. Coarse granularity is acceptable (project →
  capability → component → source/test evidence). **Capability identities come
  from the governed project's own declared artifacts**; code that maps to no
  declared capability renders Unknown — never silently inferred into a
  capability. On a project whose declared artifacts are absent or incomplete,
  V0's first action is to *draft* them for owner sign-off (see writes, below);
  until signed off, drafted capabilities render as unadopted and may not
  anchor the map. **A predominantly-Unknown map on an undeclared project is
  the correct output, not a defect.**
- **Work navigation**: pending and completed work as navigable dependency
  graphs.
- **Machine-queryable endpoints** (V0-mandatory): agents consume the same
  observed truth the owner sees.
- **Propagation proof-of-concept** (V0-mandatory, per owner ruling): a minimal
  working slice on each of the three axes — tune an intent artifact and see the
  change reflected in rendered truth (intent); from one signed-off spec delta,
  dispatch one scheduled work item end to end for a worker to materialize
  (work); navigate from a code region to the spec and work that govern it
  (code).
- **Non-code writes**: under VIS-5, Syzygy writes directly only within
  `openspec/**` and `.syzygy/**`, and reaches the configured work scheduler
  through its typed adapter — including **drafting** a project's doctrine and
  shape documents (into `.syzygy/governance/`) as first-pass work on a newly
  governed codebase. Drafting is not adopting: drafted doctrine is stored and
  rendered as unadopted until the owner signs off (VIS-4). Syzygy never
  writes code.

**Increments:** V0 may ship in increments. No increment lacking both escape
properties — endpoints in real actuator use *and* the three-axis propagation
proof-of-concept — may be described as V0-complete, as validating the thesis,
or as more than an observatory.

V0 trust floor: trust-and-evidence.md (normative statement); release-blocking
for Syzygy's own releases.

Proving ground: the owner's other live projects — real, messy, already
running, mostly *undeclared* (which is why first-pass drafting is V0 work).
Self-observation of the Syzygy repo is not the credibility test.

## V1 — the harness

Directional, to be concretized through RFCs and specs:

- Gap computation between declared intent and observed state, surfaced as
  navigable objects with an upward path: evidence may indict the spec.
- Human-triggered propagation at full breadth: from a tuned vision or spec,
  dispatch scheduled work for workers to materialize ("specifications for
  features, beads for bugs" — a bug routes directly to work only when an
  existing spec already defines the correct behavior; otherwise it is a spec
  gap first).
- Provenance surfaces: structured summaries linking each unit of work to the
  spec and vision that motivated it.

## Deferred, with rationale

| Capability | Why deferred |
|---|---|
| Live agent-fleet monitoring | Meaningless without the observed truth it would annotate; doctrine mandate (vision.md) keeps it named and sequenced on every roadmap with entry criteria |
| Convergence certificates | Semantics (invalidation, expiry) deliberately deferred to an RFC; post-V1. Certificate references elsewhere are future-tagged |
| Autonomous spec adoption | Permitted in principle; opening the gate requires the adjudication RFC **and** an owner doctrine amendment (VIS-4) |
| Full regeneration flows | North star, not scope; feasibility risk (spec completeness) attacked by RFCs first |
| Multi-user collaboration | Owner-first; access serves one owner's devices, not teams |

## Platform and audience

- Local-first daemon with a browser app (current shape; RFC-open); reachable
  beyond localhost only via authenticated, TLS-protected access limited to the
  owner's own devices (SEC-1). Remote backing dependencies under SEC-2's
  consent rules.
- Observed-project code execution: opt-in, profiled, and blocked until the
  execution-profile RFC is accepted (SEC-3).
- Audience: the owner's portfolio practice first; open-source public second.
  Substrate tools are adapters (architecture.md); the designated initial
  substrate is the public ai-bootstrap toolchain (README glossary).
- Stack (languages, databases, frameworks) is **not chosen here**; structural
  commitments are only those in architecture.md.

## Evidence of success (stage-labeled, each with its artifact)

Success tests are human judgments (vision.md); each declares an evidence
artifact so its verdict is reviewable later. Absent its artifact, a test
renders Unknown, never met.

- **V0 — instinctive-open test:** Syzygy displaces the README/sample-script/
  ad-hoc-investigation ritual as the owner's first stop. *Artifact:* recorded
  first-stop sessions over time.
- **V0 — comprehension test:** a reader who has never seen the project, using
  the spatial view, names its top-level declared capabilities and at least one
  region of absent or Unknown evidence — and explains the project more
  accurately than before using it. *Artifact:* the recorded walkthrough,
  checked against the declared artifacts.
- **V0 — agent-consumption test:** agent workflows on the proving-ground
  projects consume Syzygy endpoints as their source of observed truth **in
  real use** — a workflow written solely to satisfy this criterion does not
  count. *Artifact:* the named workflows and the commits/sessions that used
  them.
- **V1 — fleet-account test:** at the end of an orchestration day, the owner
  can produce, from Syzygy alone, an accurate account of what the fleet
  changed and why, without reading raw diffs. *Artifact:* the account itself,
  linked to the day's work items.
- **V1 — cost-of-discovery test:** broken assumptions that previously surfaced
  at deployment now surface at spec or observation time. *Artifact:* named
  instances recorded as they occur.
- **V1 — early-surfacing test:** alignment drift and underspecification
  surface in Syzygy before deployment surfaces them. *Artifact:* the surfaced
  findings with their timestamps relative to deployment.
