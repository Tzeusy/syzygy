## Dispositions

### 1 — the machine answer does carry each listed source's path today; the clause the patch cites guarantees the identity, not the path (note)

**Open.** Raw line 134. [Observed by the reviewer, static reading at
`d6b3784f`] `GET /api/poc` serves the whole `PocModel`, and each
`projectShape.sources[]` element carries `path` as well as `identity`. The
patch attributes the path to PWB-REQ-011's machine recovery, which makes
recoverable the source identity, not the path; PWB-REQ-001 binds the
source-path population into the machine answer. The delta's [Unknown] is
honest and answerable. Suggested repair: cite PWB-REQ-001 beside
PWB-REQ-011.

### 2 — "visible label" is defined as text content, which is not the visible label for every element (note)

**Open.** Raw line 175. Text content includes hidden descendant text, is
empty for an `input`, and concatenates a `select`'s options. The
distinct-name rule still binds such elements. Suggested repair: one
qualifier ("its rendered text", or excluding hidden descendants).

### 3 — whether the browser computes a name for an element inside a closed `details` is not established (note)

**Open.** Raw line 195. [Unknown] Two oracles could group those elements
differently. Suggested repair: one sentence naming the procedure (open the
disclosure first, or use an independent accessible-name implementation).

### 4 — an element can be in the heading population twice, at two levels (note)

**Open.** Raw line 212. An `h2` with `role="heading" aria-level="3"` falls
in both halves; an `h3` with `role="presentation"` still counts. Polaris
emits none of these today [Inferred]. Suggested repair: "each element
once, at its computed level".

### 5 — C's hidden-element exclusions differ from A's (note)

**Open.** Raw line 225. A also excludes text under `visibility` other than
`visible`; C does not, and neither excludes `inert`. Signed together, the
two requirements would define "hidden" two ways on one page. Suggested
repair: one shared definition.

### 6 — the closed page list and the open "every Polaris page served" agree only by today's route table (note)

**Open.** Raw line 235. A future Polaris page would be served and in no
list, and the tailnet-mount forms are not mentioned. Suggested repair: one
clause saying the list is the whole population, or that a new page needs a
new list.
