## Scope

Exactly the populations in the generated table below, in the classes the
table gives, and nothing else:

- **target-content** and **composite**: content read under an in-force
  observation consent for one of these `(project:syzygy, repository)` pairs,
  and validated stage artifacts computed from it (RFC5-14):

{{ADMITTED_REPOSITORIES}}

- **target-metadata**: the source ids, classification bases, exclusion flags
  and closed exclusion reasons of the same pairs' sources, with no body.
  Excluded sources' metadata may leave: it names no content, and a repository's
  paths are tree metadata (`code-structure`) of a public target.
- **instruction-text**, **envelope-control** and **run-profile**: text authored
  by Syzygy, classified by the generator-authored-request-text rule of
  `project:syzygy`'s effective public-source screening scope, which names each
  by symbol or file; this consent does not classify it.

Every other source of `project:syzygy` content is outside this consent,
including the Butlers repository, the rest of Syzygy's own repository and any
work history, and stays unsent.

## What a request carries

A request is one canonical-JSON envelope built by `runGenerationPipeline` in
`packages/polaris-generation-core/src/pipeline.ts`. The table is GENERATED by
`scripts/derive_generator_sent_text.mjs --table` from the code, and
`scripts/build_public_repo_admission.py --check` fails when this record's table
differs from a fresh derivation; a field with no class makes the derivation
fail. Each field has exactly one class.

{{CARRIED_TABLE}}

The `generate` port receives the six fields in the last block of rows. Of
them the route sends `system` as the system prompt and `input` as the user
message; `stage`, `permit` and `signal` are never sent, and the schema is
carried inside `input`. The audit record carries the envelope digest and the
prompt version; the schema version is bound through that digest.

Beyond these fields, the route adds only the bytes that its registered
provider execution route entry lists as fixed by the runtime. A request
carrying any other byte, header or field, or a field outside the table, is
refused at the single egress check.

## Conditions

- Only content screened under `project:syzygy`'s effective public-source
  screening scope may be sent, and only the generator-authored text its
  generator-authored-request-text rule names. Excluded or unclassifiable
  content is never sent (RFC5-14, RFC5-16); a request with a field outside the
  generated table, or generator-authored text the rule does not name, is
  refused.
- A composite's class is computed from what it embeds; one whose class cannot
  be determined is refused and the refusal shown (RFC5-14).
- Every transmission passes the single egress check and emits an audit record
  (RFC5-15).
- The model sees only what each request carries. The route invokes no tools
  on the provider's or its runtime's side (no file access, command execution,
  web access or other tool), and adds no context of its own:
  {{ROUTE_CONTEXT}}
- The route sends nothing to any destination other than the provider:
  {{ROUTE_TELEMETRY}}
- This record's own condition: provider output is generated editorial draft.
  It is never recorded as an Observed claim, as adopted intent, or as the
  target project's own statement. It is shown only on the local daemon's
  generated editorial draft view or as a static file in the run directory,
  and is never published.

## Effect

Without an effective owner act over this record's exact bytes, no content
reaches this provider, and the generated draft layer renders Unknown
(`unconsented-source-or-provider`) (REQ-polaris-generation-001). Revocation
is prospective (RFC5-13).
