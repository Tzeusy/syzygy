## G1 — completeness critic (mandatory; no verdict)

*What readiness dimension could this project fail that no question above would catch?*

Four, offered for upstream amendment of the instrument (§9):

1. **Assurance independence.** The entire governance model rests on "fresh-context independent review" (CC-REV-1, CC-REV-4, VIS-3, and this instrument's own §2). No question asks whether the reviewer is independent *of the failure mode*. Here every reviewer, and this gate's administrator, is an instance of the same model family that authored the corpus — so a systematic blind spot shared across the family is invisible to the mechanism designed to catch it, and `NORMATIVE-CHANGE-WORKFLOW.md:181-183` says so in as many words. Proposed **F5 [U]**: *"Is the project's assurance mechanism independent of the thing it assures — would an error shared by every available reviewer be detectable, and by what?" Fails when: independence is procedural (different session) rather than substantive (different failure modes), and no artifact says so."*

2. **Instrument capture.** §7 anticipates generalizing this gate into skills; nothing asks who audits the gate. A project can be steered toward passing questions rather than toward readiness, and a single administrator running both authoring and administration cannot see it.
