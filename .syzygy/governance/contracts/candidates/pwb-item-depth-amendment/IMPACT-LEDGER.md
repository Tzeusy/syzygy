## Discovery method

[Observed] Two methods ran over all **1,816** paths of `git ls-tree -r -z
--name-only 4d51679`: **1,812** decoded as UTF-8 and **4** PNG evidence files
were binary remainders.

1. Python `re` over every decoded file. Literal predicate:
   `PWB-REQ-015\b`. Run predicate:
   `PWB-REQ-(\d{3})((?:\s*(?:/|,|\.\.|\band\b)\s*\d{3})+)`, expanding
   `..` as an inclusive range and selecting a match whose numbers include 15;
   case-sensitive, over the whole file text (a match may span a line break).
2. `git grep -l -F PWB-REQ-015 4d51679 --`, which independently reproduced the
   literal count.

The literal predicate returns **49** files, the same count the second method
returns. The run predicate adds **10** decoded files with no literal, for a
union of **59** citing files. The four binary remainders were enumerated
separately and the fixed-string search reports no match in them. This
package's own files are outside the figures; the helper script is not tracked,
so the predicates above are the whole method.

[Observed] Seven tracked packages patch the same PWB `spec.md`. The builder
classifies each by searching every hunk's old and new text in the current spec:
**6** are already applied (container-shape, dismissal-expiry, exact-source

package in both orders and must give identical bytes.

(`+`/`-`, not header) lines that contain `PWB-REQ-015`: **0** are in a

This package asserts no successor-chain position; adoption order among

manifest, which is derived-byte collision, not semantic precedence.

## Failure and regeneration boundary

`scripts/build_pwb_item_depth_amendment.py` fails closed when the patch target
set is not exactly the six subjects above, a patch no longer applies, the
manifest differs, generated dependencies drift, required semantics disappear,
the signed requirement was edited in place, the contract-coverage generator's
own `--check` fails over the proposed bytes or its regenerated summary differs,
a sibling spec patch is neither
pending, applied nor declined, or a pending sibling composes differently in
the two orders. `--write` is deterministic and writes only the inert
candidate's derived patches and manifest; `--check` is read-only. `--apply
--at-adoption` writes the six signed subjects, refuses without the flag, and
refuses unless the whole package verifies, so a failed check leaves every
target byte unchanged; `scripts/record_versioned_signoff.py` is its only
caller.

This package leaves the coupled `PROJECT-STATUS.md` battery, hosted workflow
and count sentence alone until sign-off, as the CG-26 triple requires. The
semantic delta's answer-first relation diagram repeats the proposed text and
adds no claim (CC-REV-8).
