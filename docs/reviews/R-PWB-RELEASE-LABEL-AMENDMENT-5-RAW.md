## Findings

**Finding 1 — the citation predicate leaves the cite's visible text free, so a sentence naming the revision can be cast as a citation, and the text's "therefore never a stamp" does not follow** (revise)

The proposed requirement:

- "A citation is an element holding a cite and its stamp, and no letter or digit outside the cite's text and the stamp's."
- "The cite names, by its identity, one anchor the machine narrative serves or one source record the machine answer serves at the same evaluation, and the stamp's whole text is the revision that record carries …"
- "A revision id in a sentence, a heading or any other running text is therefore never a stamp."

The decide-line checks three things:

- the citation names a served record;
- there are no letters or digits outside the cite and the stamp;
- the stamp's text is that record's revision.

Nothing constrains the cite's own text. [Observed] In the implementation the cite names its anchor by attribute, not by text: `anchorAttrs` writes only `data-anchor-id` (`polaris.ts` lines 210–217). The cite texts are `git-ls-tree`, a source path, `beads-dolt`. The ledger treats those existing citations as stamps "once the element around each pair holds nothing else". So naming "by its identity" is satisfied by the attribute, and the cite's visible text can be any words.

Falsifier the text does not catch. On `/polaris`:

1. The page opens with one label unit, so the lead rule holds.
2. It renders the shape statement (`polaris.ts` line 1190) as `<span class="citation"><cite data-anchor-id="A">Declared project shape of butlers at revision</cite> <code>1a2b3c4d5e6f</code></span>`, where anchor A is served and carries that revision.
3. It does the same for the "Revision …" identity line (line 1209) and the currency-probe sentence (line 466).

This page passes every decide-line:

- one label unit, first in document order;
- every swept occurrence lies in a label unit or an excepted element;
- every stamp sits in a citation whose cite names a served record carrying that revision;
- no letter or digit lies outside the cite and stamp.

Yet the revision is named in sentences outside any label unit. That is what "Polaris names the observed revision only in a label unit" forbids, and what "therefore never a stamp" claims cannot happen. The falsifier limb "a naming of the observed revision marked as a provenance stamp" is broader than its listed cases ("a stamp outside a citation, a citation holding other words, or a stamp whose cite names no served record …"), and none of those cases is met here. So, as with round-4 Note 4's limb, the implementation falsifies the requirement and still passes the oracle.

The round-4 raw's repair asked for exactly this property: "a revision id inside a prose sentence, a heading or the shape-identity section is never a stamp". The repair states it but does not decide it. It also carries into the owner's choice. Question 6's recommended option says "Every sentence, heading or identity line that names the revision shows the label instead, or drops the id. The label then leads wherever the revision is named." The text does not guarantee that.

This is narrower than round-4 Finding 1, because the lead rule now holds. But the same CC-SPEC-4 dependence on the system under test's free choice remains, in the cite text instead of the mark.

Proposed repair: constrain the cite's whole visible text to a value the checker reads from the named record, for example the source path, the observer or tool name, or the anchor's served label, so that a cite's text is decided by equality. Add that equality to the citation decide-line, and add the falsifier case "a cite whose text is not its record's served name". Alternatively, withdraw "therefore never a stamp" and the Q6 sentence, and disclose the gap as a named limit.

**Note 1 — the identity exception's record population is open** (note)

An excepted identity's whole text must equal the evaluation identity, or "the whole value of an `identity` field of a record of its own that the machine answer serves at that evaluation", and must not be a revision's id alone. The text names no closed set of records or fields: which record types, whose `identity`. So an implementation that serves a record whose `identity` value embeds the revision with other text can show it, in prose, as an excepted identity. The check that it equals a served value is real, but the served value is the system under test's own output. [Inferred] The two intended cases are the evaluation snapshot (`production-reobserve.ts` lines 85–89) and the source identity (`polaris-source.ts` line 117). Naming them, or the record classes PWB-REQ-001 and PWB-REQ-020 already define, would close it. The phrase "a record of its own" is also hard to parse: it is unclear whether "its own" refers to the element or to the record.
