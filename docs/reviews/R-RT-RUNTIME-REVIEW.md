### Findings
**RTF-1 — non-blocking — apps/syzygy/src/main.ts:125-133.** The startup guard forbidding the state dir from lying inside the governed plane compares the LEXICALLY resolved `stateDir` (`path.resolve`, no symlink resolution) against `path.join(root,'openspec'|'.syzygy')`. If an operator points `--state-dir`/`SYZYGY_STATE_DIR` at a SYMLINK whose real target is inside `<root>/.syzygy/` or `<root>/openspec/`, the lexical check passes and `authorizeStateWrite` then resolves `realRoot = realpath(stateDir)` and permits the credential write — landing a 0600 file inside the governed plane via the link. Scenario: `ln -s /repo/.syzygy/x /tmp/sd; main.js --root /repo --state-dir /tmp/sd` writes `/repo/.syzygy/x/machine-credential.token`. Non-blocking: operator-controlled startup misconfig, not request-reachable; a defense-in-depth gap in the one governed-plane startup check, not a runtime write escape. Fix: `realpathSync` the nearest existing ancestor of `stateDir` before the containment comparison, mirroring the two write-guards. [Observed]
