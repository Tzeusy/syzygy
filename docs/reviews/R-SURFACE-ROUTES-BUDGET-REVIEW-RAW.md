1. [revise] The new shared `afterAll` silently swallows a `browser.close()` failure (`apps/three-surface-poc/src/surface-routes.test.ts:303-306`):
   ```
   afterAll(async () => {
     if (page !== undefined) await page.close().catch(() => undefined);
     if (browser !== undefined) await browser.close().catch(() => undefined);
     if (daemon !== undefined) await daemon.close().catch(() => undefined);
     ...
   ```
   `browser.close()` runs `closeDisposableBrowser` (`apps/three-surface-poc/src/cdp-browser.ts`), which was hardened by commit 9162d62 specifically to *throw* — `private browser profile still held by N process(es)` / `private browser profile drain did not verify two empty scans before deadline` — when a private Chrome process group fails to fully exit. That throw is the load-related orphaned-Chrome canary the acceptance criteria ask about, and `.catch(() => undefined)` here discards it unconditionally, so a drain failure can no longer fail this test file. This is a real deviation from the codebase's own established convention: the two other browser-launching suites let `browser.close()` propagate uncaught (`apps/three-surface-poc/src/orrery.browser.test.ts:27`: `await browser?.close();`, `apps/three-surface-poc/src/polaris-accessibility.browser.test.ts:85`: `await browser?.close();`), and the prior version of this exact test (via `withBrowserPage`'s try/finally, `cdp-browser.ts`) also let it propagate. `daemon.close().catch(() => undefined)` is fine (matches the file's pre-existing pattern at line 29 and elsewhere), and `page.close()` is lower-stakes, but the `browser.close()` swallow specifically undoes 9162d62's detection for this file. Fix: drop the `.catch` on `browser.close()` (or log-and-rethrow) so a drain failure still fails the suite.
