# Generator RFC1–4 consequence mapping

Candidate analysis, not adoption, implementation authorization or a complete
per-limb discharge. The [structured evidence](../evidence/polaris-generator-rfc1-4-coverage-2026-09-12.json)
records current source and subject digests, owning clause text, retained locator
units, mapped candidate scenario populations and mandatory supporting documents.

[Observed] The old reconciled inventory contains 136 defined clauses and 904
source units. Each retained quotation matches its current owning clause after
whitespace normalization. Current definitions were independently enumerated,
including lettered headings. The units include context and compound outcomes;
904 is not a count of independent implementation requirements. Their older
unmapped/needs-decomposition labels were not treated as current verdicts.

that unsupported claim.

## Two precise follow-ups

**R14-1 — Workspace applicability subject.** The current proposed N/A subject
names RFC7 workspace/portfolio consequences. RFC3-10 through RFC3-13 own the
corresponding workspace manifest residence, closed fields, truth boundary and
project-identity references. Extend the reviewed applicability subject to those
exact consequences if the intended operation still introduces no workspace
manifest or composition. This is a narrow owner scope disposition, not a request
to implement a workspace platform. Until adopted it remains owner-pending.

**R14-2 — Typed relation adaptation.** The generic asset schema supports curated
relationships, but that is not permission to reinterpret kernel relation kinds.
For any exposed owning relation, the adapter must preserve the distinctions among
declared-dependency, depends_on and implementation mappings, retain typed owning
identity, and allow nonfunctional placed_in cardinality. Bind that behavior in
its adapter mapping or explicitly identify the curated-only operation that does
not expose those kernel relations. RFC1-25(b/c/d) and RFC4-26 make this a concrete
source-to-asset semantic issue. No new graph subsystem is requested.

The source-root asymmetry is not a new generator specification gap: the exact
approved CAP1 scenarios already exist. The new source adapter must demonstrably
consume those results rather than independently invent registration behavior.
Likewise, a missing scheduler signal does not require a new generator status
value: EXECUTION-PHASES preserves the affected consumer's refusal boundary.

## Evidence limits

This is a current clause/scenario mapping and targeted overlap assessment. It is
not a fresh independent normative-coverage verdict over every limb, nor runtime
conformance. The preserved locator units remain available for that final review;
phase clauses still require the actual adoption/implementation acts. No candidate
or source files were edited by this pass. No project-body reads or provider
calls occurred. A passing reference-integrity check cannot close the generator's
owner-flow, two-project or changed-source quality requirements.
